# 卡片编辑、保存与分享

## 编辑与保存

编辑器修改先进入页面草稿，不立即覆盖原卡。工具页提供“保存”（保留原 ID）、“另存为…”（指定新名称与新 ID）和有修改时出现的“放弃修改”；列表“更多”中的“复制”可快速创建独立副本。复制会重新生成内嵌特性、规则段和威能 ID，保留原版对照快照。离开有修改的卡片时提供保存／复制／放弃／继续编辑；刷新或关闭页面有离页提示。恢复草稿独立保存在 IndexedDB，重开页面后可恢复编辑副本、导出或明确移除；丢弃修改会清理本页恢复草稿。

提交保存使用 IndexedDB 主存档，资源与术语原子写入；旧 localStorage 仅用于迁移和不支持 IndexedDB 时的兼容模式。提交后若显示“有未保存修改”，应重试或导出备份。全库备份和当前卡导出包含当前编辑稿，可在存储不足时保留成果。术语自动收录独立保存，不提交卡片草稿。

## 单卡与多选

预览提供单卡 JSON 和可编辑 PNG。神兵宝甲／修行传承／成道之途可以选择完整卡、概要卡或单张附属威能；附属威能的独立导出携带 moves 条目，概要卡携带整个父资源数据，图片内容与恢复范围因此不同。装备概要仍保留等级版本与各版本的价值、淬炼、暴击数据，导入后可继续编辑。

工具页列表进入“批量操作”后提供手动多选、选择搜索结果、合并 JSON，新增单卡 JSON ZIP 与 PNG＋JSON ZIP。顶栏“我的资源”支持跨九类资源检索、多选与打包。一次 ZIP 最多 200 张卡，文件总量不超过 100 MB；图片顺序生成，失败不下载不完整包。每张卡的文件名包含序号，避免重名覆盖。

PNG 使用标准未压缩 UTF-8 iTXt 文本块，关键词为 WuxiaResource，携带原有版本 1 资源备份。写入与导入验证 PNG 长度、CRC、结构，元数据上限 20 MB。图片可正常浏览，无需联网；数据包括不显示在卡面上的来源和原版对照。截图、转码、社交平台压缩或剪贴板处理可能删除元数据，普通图片不执行 OCR，也不宣称完整还原。

## 导入

顶栏“导入全库／卡片”接受版本化或旧版 JSON、可编辑 PNG、卡片 ZIP。工具页“导入卡片”使用同一校验流程。导入先预览再选择：保留本地／覆盖重复 ID／全部生成独立副本。全部校验成功后才执行，失败不改作者数据。

ZIP 支持每张卡的 PNG 和 JSON；数据一致的同类同 ID 条目合并一次，数据不同则拒绝整包，避免歧义。只读取 JSON／PNG，不写入磁盘路径。解压总量限制 100 MB、500 个文件，拒绝超限；卡片包可附带术语，重复术语合并；同一标准词出现不同置换时拒绝整包，需拆开导入。携带自定义配色库的工作区 JSON 请单独导入。导入前须先处理当前未保存稿。

工具页列表“从 4E 模板创建”直接读取已下载的只读资料缓存，可切换资料包、搜索并查看原版正文，只显示当前工具适用的类别。选择后导入独立可编辑资源，保留来源、原始字段和转换提示；种族按当前根骨／出身／先天命格工具拆分，附属威能从同一缓存资料包解析。未下载时提供资源管理入口，不自动联网。未保存的编辑稿须先处理，已有资源和只读缓存不会被覆盖。4E JSON 文件仍可通过“导入卡片”导入。

## 验证边界

自动验证中文及未知字段 PNG 往返、重复元数据替换、CRC 损坏拒绝、PNG／JSON ZIP 去重、导入大小和重复 ID、原版引用转换、保存原卡不变及导航保护。实际截图尺寸、PNG 像素效果、作者信息在不同屏幕的单页布局及浏览器下载交互仍按用户要求交由部署后人工审核。

## 工作区布局

顶栏区分“我的资源”“关键词与术语”“4E 参考资源”和“数据管理”；全库备份、文件导入位于数据管理。当前卡片名称、保存状态和保存操作集中在卡片工具栏。新建、从 4E 模板创建及当前工具文件导入位于资源列表顶部。列表可以收起，批量模式退出后清除选择，单条复制／导出／删除位于“更多”。编辑与预览保留可拖动和键盘调整的分隔条，窄屏切换编辑／预览。

招式编辑按基础信息、使用与攻击、规则正文分组，原版正文默认折叠而转换待核对提示独立可见。术语库对齐标准词、当前显示、置换输入与操作；弹窗标题和底部操作固定，正文滚动。界面样式限定于创作工具区域，不调整卡片与导出格式。

## 分享与工作区备份边界

单卡 JSON、列表 JSON、PNG 和 ZIP 均携带当前术语配置。导入补充未有术语，保留本地已有置换。ZIP 中 JSON 和说明文本压缩，PNG 保留原压缩数据；既有未压缩包仍兼容。

全库 JSON 额外包含可选 colors 自定义配色库；导入先校验全部字段，配色按色值去重，保留本地名称并修正冲突 ID。配色与资源仍分别存储：配色保存失败时不执行资源导入；配色成功后资源保存失败则保留内存资源，按照状态提示重试或导出备份。损坏的本地配色须先处理恢复原文，不静默覆盖。配色损坏时仍可导出卡片与术语，界面明确提示配色未包含，须另行保留配色恢复原文。全库备份不包含只读模板缓存和界面布局偏好。

## 借鉴 4E NEXT

参考本地 4E NEXT 的 web/src/lib/backup.ts 对资源文件与全量备份的区分，以及 web/src/lib/storage.ts 的保存失败反馈设计。吾侠独立实现版本化卡片、PNG 元数据与 ZIP，未复制原项目源码。4E NEXT 网页存储同样使用 localStorage，不能直接提供作者存档扩容；作者存档已迁移为独立 IndexedDB 存储，旧键原文保留。
